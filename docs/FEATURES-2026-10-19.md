# Perubahan fitur dan kontrak — 19–20 Oktober 2026

Dokumen ini menjelaskan perilaku implementasi. Bukti pengujian dan kesiapan deployment dicatat terpisah; daftar fitur bukan pernyataan seluruh QA telah selesai.

## Kandidat, kontak dan periode

Setiap mapel memiliki `candidateDefinition`, `candidateVersion` dan `candidateHistory` yang dikelola server. Perubahan definisi menyimpan versi lama, aktor dan waktu; client tidak dapat mengganti riwayat dengan payload sendiri. Borang menampilkan definisi dan versi yang menjadi konteks penilaian. Simpan/review mengirim versi kandidat saat ini agar draft lama tidak masuk ke definisi baru.

Jika `collectContactPanelis=true`, panelis wajib mempunyai minimal satu kontak WhatsApp/email valid sebelum membuka borang, feedback, menyimpan atau meninjau jawaban. Setiap kanal nonkosong divalidasi, WhatsApp dinormalisasi ke E.164. `GET/PUT /profile/contact` tetap dapat diakses setelah mengganti password saat gate kontak belum lengkap. `GET /me` mengembalikan **UserView** dengan `id` dan `contactRequired` terkini, bukan claims JWT. Kontak tersimpan terpisah dan hanya terlihat pada profil sendiri serta monitoring admin/PIC yang ditugaskan.

Input tanggal proyek memakai Asia/Jakarta: mulai 00.00 inklusif, akhir 00.00 hari setelah tanggal selesai eksklusif, disimpan sebagai UTC instant. Tanggal legacy tetap sampai admin mengedit. Di luar periode, borang menjadi baca saja; server menolak simpan/review termasuk antrean offline yang tiba terlambat. Rollback tidak memperpanjang periode.

Kode error inti: `428 CONTACT_REQUIRED`, `409 REVISION_CONFLICT`, `422 PERIOD_CLOSED`. `428` tanpa kode juga dapat berarti password pertama wajib diganti. Setelah409, muat ulang konteks dan minta peninjauan, bukan menimpa otomatis.

## Putaran, review, pengecualian dan snapshot

Simpan jawaban memakai `roundNumber`, `roundRevision`, `candidateVersion`, `version`, jawaban valid, catatan opsional maksimal 1000 karakter, `reviewed` dan `idempotencyKey`. Catatan disimpan bersama jawaban valid. Replay dengan kunci/payload sama tidak membuat perubahan ganda; kunci sama dengan payload berbeda ditolak. Setelah rollback, revisi round naik dan setiap butir perlu diakui kembali melalui simpan `reviewed:true` atau `POST /panelist/submissions/:itemId/review` dengan versi respons/round/kandidat yang sesuai.

PIC pada mapelnya dapat mengeluarkan panelis dari round aktif dengan alasan dan konfirmasi `KELUARKAN PANELIS`, lalu membatalkannya. Ini tidak menonaktifkan akun atau menghapus jawaban. Denominator monitoring/finalisasi mengikuti peserta efektif round tersebut, dengan jumlah respons yang masih perlu review. Kontak/catatan monitoring terbatas scope admin/PIC.

Finalisasi menyimpan snapshot immutable round+revision: roster/status peserta saat finalisasi, respons, statistik butir/mapel, definisi kandidat dan aturan pembulatan. Finalisasi ulang menambah arsip. Status akun/roster hari ini tidak menghitung ulang hasil final. Snapshot lama tanpa roster lengkap diberi `rosterComplete=false`; status historis tidak ditebak. Putaran yang dikirim ke borang tidak memuat snapshot jawaban peserta lain.

Umpan balik panelis berasal dari snapshot final putaran sebelumnya dengan marker nilai sendiri. Diskusi PIC hanya mengirim distribusi anonim dan metadata butir. Bila n < 3, nilai individual disembunyikan; nama, kontak dan catatan tidak masuk distribusi diskusi.

## Laporan, dampak dan evaluasi

[Laporan/dampak/evaluasi](../../docs/features/reporting-impact-evaluation.md) menjelaskan halaman, statistik, ekspor CSV, template XLSX dan privasi evaluasi. API laporan menerima `round` dan `revision`, mempunyai manifest dan daftar arsip, serta membedakan provenance legacy. Raw CSV menambahkan `rosterComplete`, `activeAtSnapshot`, `removedAtSnapshot` dan `exclusionReason`; status historis kosong jika snapshot tidak menyimpannya. Kontak/password/hash/token/catatan tidak diekspor dalam CSV umum.

Evaluasi panelis sendiri tidak memblokir simpan nilai, tidak memerlukan gate kontak dan boleh dilakukan pada proyek aktif/selesai sampai `evaluationClosed=true`. Agregat admin menyembunyikan rincian bila n menjawab < 3. Salin proyek hanya membuat draft struktur baru; akun, butir, periode, kontak, respons dan hasil tidak ikut disalin.

## Akses dan operasi

`GET /audit-events` khusus Admin Super, dengan filter proyek, aksi serta pencarian literal ID/nama/username. Nama di respons berasal dari identitas saat ini; event tetap menyimpan ID, aksi, outcome, requestId dan waktu. Tidak ada endpoint update/delete audit atau melihat password pribadi. Login, gagal login, ganti/reset password dan perubahan penting diaudit tanpa rahasia.

Login memakai counter Redis atomik+TTL untuk username dan IP; blokir sementara429 dengan `Retry-After`. Redis/kontrol keamanan gagal menghasilkan503 tanpa bypass. Reset/ganti password menaikkan `authVersion` agar access/refresh lama ditolak. IP forwarded hanya dipercaya dari proxy yang dikonfigurasi.

Startup memisahkan bootstrap superadmin dari butir contoh: `SEED_DEMO_ITEMS=false` secara default. Baca [migrasi v3](MIGRATION.md#versi-3--revisi-kontak-dan-audit), [OpenAPI](openapi.yaml), dan [runbook instalasi/HTTPS/backup/restore](../../deployment/OPERATIONS.md). Restore drill produksi dan SLA harus dibuktikan operator di lingkungan terisolasi.


## Penyempurnaan tampilan — 20 Oktober 2026

Riwayat aktivitas memakai filter form yang konsisten dan daftar jenis aktivitas dalam bahasa Indonesia. Respons audit menambahkan `targetLabel`, `projectName`, `subjectName`, dan `roundNumber` untuk menjelaskan target proyek/mapel/putaran. Identitas event tetap tersimpan seperti semula; label menggunakan data yang masih tersedia, dengan keterangan khusus bila target telah dihapus. ID teknis tidak menjadi label utama.

Ringkasan akun dan bank butir memakai satu baris empat informasi yang lebih pendek. Fokus input login menggunakan border netral tanpa dua lapis highlight hijau. Panduan ON kontak dan subtitle panduan umum pada halaman administrasi/wizard telah dihapus; status tersimpan, error, dan alasan penguncian tetap terlihat.

Subtitle teknis pada header borang panelis tentang simpan otomatis dan sinkronisasi10 detik juga dihapus. Keterangan periode/status baca saja hanya muncul ketika borang memang terkunci.

Profil Kontak memakai kartu form aplikasi dengan judul bagian “Kontak Panelis”, tanpa judul profil berulang di dalam kartu login. Input WhatsApp/email memakai field beradius8px, padding konsisten dan token ukuran teks. Tombol simpan berada di kanan pada desktop dan selebar form pada mobile. Field yang sama juga digunakan saat melengkapi kontak pertama kali; validasi serta alur simpan tidak berubah.

## Kode mapel manual dan review proyek — 20 Oktober 2026

Modal tambah mata pelajaran menyediakan isian wajib **Kode mapel** dan **Mata pelajaran**. Kode berisi 2–20 karakter, diawali huruf, lalu huruf/angka/`_`/`-`; server memangkas spasi luar dan menormalkan huruf besar. Kode dan nama harus unik. Katalog menampilkan kode agar dapat digunakan pada template Excel. Kode lama tetap berlaku dan tidak diganti otomatis.

`POST /subjects` menerima `{ "name": "Sejarah", "kode_mapel": "SEJ" }`; `code` diterima sebagai alias. Jika keduanya dikirim, nilainya harus sama setelah normalisasi. Kode tidak valid menghasilkan422, kode/nama duplikat409. Respons tetap menggunakan properti `code`.

Excel alokasi butir langkah 2 tetap memakai header strict `mata_pelajaran,id_butir`. Kolom `mata_pelajaran` dapat berisi nama atau kode mapel, tanpa membedakan huruf besar/kecil. Input yang sekaligus cocok dengan nama satu mapel dan kode mapel lain ditolak sebagai ambigu. Validasi seluruh baris tetap berlaku: satu baris bermasalah membatalkan seluruh impor. Template analisis dampak tetap memakai kode mapel. Identitas prefill pada template langkah 3/4 tetap mengikuti baris template.

Langkah 5 memakai ringkasan empat informasi (mapel, butir, PIC, panelis), panel akun, serta panel kesiapan yang mengikuti gaya aplikasi. Garis antar langkah menggunakan tinggi2px dan berada di tengah lingkaran; tidak lagi beririsan dengan area teks. Ujung garis berjarak12px dari lingkaran berikutnya; pada mobile, kedua ujung garis berjarak12px dari lingkaran. Alur aktivasi tidak berubah.

## Penyesuaian ukuran teks

Header bersama Admin Super, PIC, dan Panelis menyediakan kontrol **A− / A+**, dengan indikator ukuran. Ukuran dasar awal12px mempertahankan tampilan sebelumnya; perubahan per1px dibatasi12–20px. Tombol terkait dinonaktifkan saat mencapai batas. Teks biasa, menu, tabel, dan field memakai token ukuran bersama; judul/angka besar yang sudah melebihi20px mempertahankan hierarki desain semula.

Preferensi disimpan pada browser untuk origin aplikasi dan dipulihkan saat reload, tanpa mengubah konfigurasi proyek atau data akun. Bila penyimpanan browser tidak tersedia, kontrol tetap berfungsi untuk sesi halaman tersebut. Header mobile dapat membungkus kontrol. Navigasi langkah wizard dapat digeser horizontal saat teks diperbesar agar label dan garis tetap mendapat ruang; pada mobile tetap menggunakan lingkaran langkah.

## Posisi daftar butir pada borang

Daftar butir mengikuti tinggi aktual header dan panel kandidat batas lulus, dengan jarak16px di bawah panel kandidat saat keduanya sticky. Pengukuran diperbarui otomatis saat ukuran teks atau lebar layar berubah. Panel daftar butir dapat digulir sendiri bila tinggi daftar melebihi ruang di atas footer. Pada layar sampai760px, panel kandidat dan daftar butir mengikuti alur halaman tanpa sticky.
